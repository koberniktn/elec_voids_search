# elec_voids_search

Пакет для поиска полостей в периодических кристаллических структурах и отбора позиций, подходящих для внедрения иона. 
Объединяет в себе сеточный поиск и анализ вершин Вороного для первичного нахождения потенциальных полостей, проверяет размер полостей и сравнивает их окружение с окружением уже занятых позиций.

По умолчанию рассматривается Li⁺. Пробный элемент, его степень окисления и параметры отбора можно менять. 
Степени окисления элементов структуры задаются вручную. 

## Этапы скрининга

1. **Первичный поиск.** Независимо находим локальные максимумы расстояния до ближайшего атома на сетке и вершины периодической диаграммы Вороного. На этом этапе размер иона не проверяется.
2. **Объединение списков.** Собираем кандидатов обоих методов с сохранением источника и исходных координат.
3. **Слияние близких точек.** Объединяем кандидатов в кластеры. По умолчанию оставляем в каждом кластере точку, наиболее удалённую от ближайшего атомного центра.
4. **Отсев по симметрии.** Оставляем симметрично неэквивалентных кандидатов.
5. **Геометрический отсев.** Рассчитываем радиусы атомов каркаса и пробного иона с учётом локального окружения. Проверяем, помещается ли ион в полость. Основной режим допускает перекрытие до 10% радиуса пробного иона; допуск настраивается.
6. **Сравнение координации.** Сопоставляем окружение кандидата с занятыми сайтами пробного элемента: состав первой сферы, длины связей, углы отдельно по парам элементов и дескрипторы ячейки Вороного.
7. **Проверка расстояния до занятых сайтов.** Сравниваем расстояние от кандидата до ближайшего занятого сайта пробного элемента со средним расстоянием от каждого занятого сайта до ближайшего другого такого иона, учитывая периодичность и заданный допуск.

После геометрии координационный и дистанционный фильтры по умолчанию работают **независимо**. Дополнительно рассчитываются оба порядка их последовательного применения. Маршруты можно настроить. Координаты при отборе не уточняются и не смещаются; данные передаются между этапами в памяти.

## Установка и запуск

Используется Python 3.12. Из корня репозитория установите зависимости:

```bash
python -m pip install -r examples/full_pipeline/requirements-notebook.txt
```

Для работы без Jupyter достаточно [зависимостей пакета](elec_voids_search/requirements.txt). Пакет запускается из исходников: корень репозитория должен быть доступен для импорта. Готовый ноутбук настраивает этот путь автоматически.

Расчёт одной структуры с итоговыми таблицами и CIF:

```python
from elec_voids_search import SearchConfig, run_structures

report = run_structures(
    files="examples/full_pipeline/inputs/LiCl_one_Li_vacancy.cif",
    oxidation_states={"Li": 1, "Cl": -1},
    search_config=SearchConfig(geometry_overlap_tolerance_percent=10.0),
    output_dir="results/LiCl_vacancy",  # новая папка
)

report["summary"]       # количества кандидатов на всех этапах
report["summary_norm"]  # те же количества на формульную единицу
report["branch_steps"]  # результаты каждого шага финальных маршрутов
```

Для нескольких структур передайте список путей или словарь `{имя: путь}`. Если составы различаются, задайте заряды словарём `{имя: {элемент: степень_окисления}}` с теми же именами.

Меняйте только нужные настройки: `SearchConfig` управляет поиском и геометрией, `PostGeometryConfig` — финальными фильтрами и их последовательностями. Остальные значения сохраняют настройки по умолчанию. Описание параметров, единиц и рекомендаций — в [PARAMETERS.md](elec_voids_search/docs/PARAMETERS.md).

## Навигация по проекту

- [screening_pipeline.py](elec_voids_search/screening_pipeline.py) — `run_screening`, полный расчёт одной структуры.
- [screening_batch.py](elec_voids_search/screening_batch.py) — `run_structures`, запуск для одного или нескольких файлов и подготовка общего отчёта.
- [screening_results.py](elec_voids_search/results/screening_results.py) — `export_screening_results`, сохранение уже рассчитанных результатов без повторного поиска.
- [config.py](elec_voids_search/config.py) — общие настройки поиска и геометрии.
- [tests/](elec_voids_search/tests/) — проверки функций и сравнение с сохранённым контрольным прогоном.

Модули: `candidates/` — поиск и объединение, `geometry/` — размер полостей и радиусы, `descriptors/` — описания окружения, `filtering/` — финальный отбор, `symmetry/` — симметрия и периодические группы, `results/` — экспорт, `tools/` — продолжение расчётов и диагностика.

## Примеры и результаты

В [examples/](examples/README.md) находится пример полного скрининга **семи соединений**, включая две структуры с искусственно удалённым Li. Входные CIF, ноутбук, итоговые таблицы и визуализации перечислены в [описании примера](examples/full_pipeline/README.md).

При заданном `output_dir` сохраняются общие таблицы `summary.csv`, `summary_norm.csv` и `branch_steps.csv`, настройки и сведения о запуске в `metadata.json`. Для каждого соединения создаются таблица координат со статусами кандидатов, данные о радиусах и контрольных сайтах, а также папка `cif/` с кандидатами после каждого этапа.

CIF содержат исходный каркас и фиктивные X-маркеры полостей для визуализации. Без `output_dir` результаты остаются в памяти; `export_cif=False` отключает экспорт визуализаций. Существующая папка результатов не перезаписывается.

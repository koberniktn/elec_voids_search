# Вороной-координация и независимые ветки после геометрии

Новая оркестрация находится в screening_pipeline.py. Поиск кандидатов, объединение и симметрия не изменены. По отдельному согласованию геометрический допуск переведён в проценты радиуса пробника (дефолт 10%); архив базовой версии сохранён. Старый environment_matching.py остаётся прежним исследовательским методом жёсткой первой сферы; новый фильтр использует weighted_voronoi.py и не вызывает его.

По умолчанию выполняется схема:

```
геометрически прошедшие кандидаты
    ├── coordination: взвешенное окружение Вороного
    └── li_distance: прежний критерий расстояния до Li
```

Это независимые выборки. Прохождение Li–Li не требуется для входа в координационную ветку. Общего единственного «финального списка» по умолчанию нет: доступны обе ветки и их пересечение/разности. Координаты не перемещаются и не усредняются.

## Запуск из ноутбука

Для продолжения с сохранённой геометрии:

```python
from elec_voids_search.post_geometry_config import PostGeometryConfig
from elec_voids_search.screening_pipeline import continue_from_saved_geometry

result = continue_from_saved_geometry(
    input_cif, baseline_candidates_csv,
    oxidation_states={"Li": 1, "Ge": 4, "P": 5, "S": -2},
    config=PostGeometryConfig(),
    output_dir=new_output_folder,  # можно не задавать: тогда всё в памяти
)
coordination_passed = result["branches"]["coordination"]["passed"]
li_passed = result["branches"]["li_distance"]["passed"]
```

Чтение выбирает in_geometry=True (либо geometry_status=passed, если in_geometry отсутствует). Прежний probe_distance_status при отборе входа не используется.

Продолжение из старой геометрической выборки не применяет новый процентный допуск и не возвращает ранее отклонённые позиции. Для сравнения с новым допуском требуется отдельный пересчёт геометрии на кандидатах после симметрии; старый список прошедших для этого недостаточен.

Для таблицы геометрических кандидатов в памяти:

```python
from elec_voids_search.post_geometry import screen_geometry_candidates
result = screen_geometry_candidates(structure, geometry_candidates, oxidation_states, config)
```

Для полного расчёта с начала:

```python
from elec_voids_search.config import SearchConfig
from elec_voids_search.screening_pipeline import run_screening

result = run_screening(
    input_cif,
    search_config=SearchConfig(geometry_oxidation_states={"Li": 1, "Cl": -1}),
    post_config=PostGeometryConfig(),
    output_dir=new_output_folder,
)
search_tables = result["search"]
filter_branches = result["post_geometry"]
```

run_screening вызывает исходный run_search до геометрии с save_results=False; затем запускает новые ветки. Сырые таблицы остаются в памяти, не создавая повторных JSON/CIF всех ранних стадий. Полный запуск и продолжение — разные явные функции, скрытого повторного поиска нет.

## Маршруты фильтрации

```python
from dataclasses import replace

config = PostGeometryConfig(paths={
    "coordination": ("coordination",),
    "li_distance": ("li_distance",),
    "coord_then_li": ("coordination", "li_distance"),
    "li_then_coord": ("li_distance", "coordination"),
})
```

Каждый маршрут начинает с одного и того же геометрического входа. Внутри маршрута следующий фильтр получает только прошедшие предыдущий. Непрошедшие и indeterminate не возвращаются в отбор; сохраняются в соответствующей таблице шага. Повтор одного фильтра в одном маршруте запрещён.

Общая сессия кэширует оценки по candidate_id, поэтому при добавлении двух последовательностей после независимых веток повторных научных расчётов для уже оценённых точек нет. Один и тот же фильтр имеет одинаковые настройки во всех маршрутах сессии. Смена настроек — новый вызов. Для сравнения порогов только координационного фильтра можно переиспользовать WeightedVoronoiMatcher.screen(..., comparison_config=replace(config,...)); изменение параметров построения требует нового matcher.

Из результата можно также передать branch["passed"] в отдельный последующий screen_geometry_candidates с другим набором paths. Это новый явно настроенный запуск на уже уменьшенной выборке; прежний поиск не выполняется. Счётчики такого запуска относятся к переданной выборке, а не ко всем исходным порам.

## Как построен многогранник

1. Все атомы пробного элемента исключаются из расчёта окружения; исходная структура не изменяется. Для занятого эталона центральный Li также исключён.
2. Вокруг исследуемой точки собираются периодические образы всех остальных атомов каркаса. В локальном облаке строится ячейка Вороного единственной пробной точки. Периодические копии искусственного пробника не добавляются, суперячейки не создаются.
3. Принимается только замкнутая ячейка с достаточной полнотой облака: радиус поиска должен быть больше удвоенного максимального расстояния до вершины. При этом любой пропущенный атом лежит слишком далеко, чтобы его биссекторная плоскость пересекала ячейку.
4. Если условия не выполнены, радиус увеличивается до явного максимума. При неудаче результат indeterminate, без скрытого принятия неполной ячейки. Проверяется сумма телесных углов 4π.

Объём — объём ячейки потенциального сайта в каркасе, не свободный объём поры за вычетом ионных сфер. Радиусный критерий на этом этапе повторно не применяется.

## Переиспользование исходных функций

- get_nonequivalent_occupied_sites, site_has_element и site_composition используются из существующего occupied_sites.py, ранее скопированного из strong_voids_screening.py.
- Один набор neighbor_weights, calc_cn_*, calc_element_fraction, calc_distance_*, calc_voronoi_volume и calc_voronoi_sphericity скопирован дословно из voronoi_site_descriptors.py в voronoi_descriptors.py. Форматирование сохранено, SHA-256 записаны в VORONOI_DESCRIPTOR_SOURCES.json. Варианты этих функций из *_counts.py не дублируются.
- Прежний screen_probe_separation вызывается непосредственно, без переписывания критерия Li–Li.
- Новое построение соседей требуется потому, что collect_site_neighbor_data/get_voronoi_neighbors из старых программ описывают другое окружение — с существующими Li и/или периодическими образами вставленного пробника. Их нельзя дословно использовать для нового определения ячейки.
- Старые compare_voids_with_occupied и compare_environments не вызываются: их единый rtol/atol=0 и AND по признакам заменены обсуждённым блочным сравнением. Сохранены привычные конструкции: циклы по таблицам кандидатов/эталонов, row-словари, отдельные DataFrame результатов.

## Дескрипторы и сравнение

Вес соседа — его телесный угол, нормированный на сумму. Показатели рассчитываются для всего каркаса и отдельно для противоположно заряженных соседей (O/S/Cl для Li+). Заряды задаются вручную. Доли и профили основной анионной части имеют больший вес; Al/Ti и прочая дальняя катионная химия остаются в полном канале.

- Координационный блок: максимум из различия химических долей и эффективного КЧ; доли сравниваются total variation, эффективное КЧ — в абсолютных единицах.
- Дистанционный блок: расстояние Вассерштейна между взвешенными распределениями расстояний по элементам, в Å. Для отсутствующего у обеих сторон элемента сравнения расстояний нет. Элемент, имеющийся только с одной стороны, отражается в химическом различии; его неопределённое расстояние не подставляется нулём. При полном отсутствии общих элементов дистанционное различие бесконечно — это явный отказ.
- Размерный блок: абсолютное различие V^(1/3), в Å.
- Блок формы: максимум из различия взвешенных угловых распределений и сферичности. Углы сравниваются отдельно для каждой неупорядоченной пары элементов (O–O, O–Cl, Cl–Cl и т. д.), через расстояние Вассерштейна. Угловые веса — произведение весов двух соседей. Различия по парам усредняются с весами, равными средним нормированным массам этих пар в двух окружениях. Для пары, присутствующей только в одном окружении, различие 180° с её весом; если углов нет у обеих сторон, угловая часть нулевая. При одном элементе угловое сравнение совпадает с прежним. Используются прежние открытые angular_tolerance_deg и пороги блоков; новых скрытых допусков нет.

Нормированные блоки объединяются взвешенным средним. Помимо среднего есть явные верхние границы отдельного активного блока и основной анионной химии/координации/расстояний/углов. Поэтому крупное основное расхождение нельзя скрыть хорошим вспомогательным признаком. Достаточно подтверждённого совпадения с одним занятым симметрийным типом.

Дополнительно обязательна первая координационная сфера: используются существующая `describe_framework_shell` и общий блок `compare_shell_geometry` из environment_matching.py. Для кандидатов и эталонов одинаково исключены все атомы пробного элемента; учитываются противоположно заряженные соседи с `d <= first_shell_distance_ratio * d_min` (дефолт 1.25). Состав сферы по элементам должен совпадать точно. Поэлементно отсортированные длины связей сравниваются по RMS (≤ 0.15 Å), углы — по отсортированным профилям пар элементов и RMS (≤ 12°). Оба ограничения обязательны независимо от объёма, сферичности и взвешенной оценки Вороного. Перестановочный поиск и дополнительное выравнивание координат здесь не выполняются. Пограничное попадание соседа в сферу зависит от открытого параметра 1.25; это рабочее определение сферы, а не универсальная химическая граница.

`maximum_primary_score` по умолчанию теперь 1.0 вместо 1.5: заданные масштабы основной анионной части не увеличиваются автоматически в полтора раза. В CSV добавлены состав и КЧ первой сферы, состав выбранного эталона, RMS длин/углов и причина отказа первой сферы. Неподходящее ближайшее окружение не компенсируется совпадением объёма. Изменение first_shell_distance_ratio требует нового matcher; допуски сравнения можно менять на кэшированных дескрипторах.

Если часть эталонов не построена и совпадение с доступными не найдено, кандидат indeterminate, а не заведомо rejected. Подтверждённое совпадение с доступным эталоном остаётся passed, список недоступных эталонов виден в результатах. Можно вместо этого выбрать немедленную ошибку reference_error_policy="raise".

## Все дефолты доступны пользователю

```python
from elec_voids_search.voronoi_coordination_config import VoronoiCoordinationConfig
from elec_voids_search.probe_separation import ProbeSeparationConfig

coord = VoronoiCoordinationConfig(
    chemical_fraction_tolerance=0.15,
    effective_cn_tolerance=1.0,
    distance_tolerance_A=0.20,
    size_length_tolerance_A=0.20,
    angular_tolerance_deg=12.0,
    sphericity_tolerance=0.10,
    primary_environment_weight=0.75,
    coordination_block_weight=0.25,
    distance_block_weight=0.35,
    size_block_weight=0.15,
    shape_block_weight=0.25,
    combined_score_limit=1.0,
    maximum_block_score=2.0,
    maximum_primary_score=1.0,
    first_shell_distance_ratio=1.25,
    first_shell_radial_tolerance_A=0.15,
    first_shell_angular_tolerance_deg=12.0,
)
config = PostGeometryConfig(
    coordination=coord,
    separation=ProbeSeparationConfig(distance_tolerance_A=0.10),
)
print(config.to_dict())
```

Это открытые рабочие настройки, пока НЕ откалиброванные новым тестовым прогоном. Они не являются гарантией прохождения известных вакансий или LATP. initial_cutoff_A=6, maximum_cutoff_A=24, cutoff_growth=1.5; численный допуск 1e-8, допуск суммы телесных углов 1e-5. minimum_face_area_A2=1e-12 предназначен только для вырожденных численных граней. significant_face_fraction=0.01 меняет отчётное значимое КЧ, но не обрезает ячейку, её объём или веса остальных признаков. Все значения определены в VoronoiCoordinationConfig и доступны через to_dict.

Пробный элемент задаётся в PostGeometryConfig.probe_element. При separation=None автоматически используются прежние дефолты Li–Li-фильтра для этого элемента. Если передан явный ProbeSeparationConfig, элемент должен совпадать. Степень окисления пробника задаётся отдельно, как и словарь зарядов каркаса.

## Результаты и компактный экспорт

- result["branches"][name]["steps"] — все шаги маршрута с evaluated/passed/rejected/indeterminate.
- branch["passed"] — прошедшие весь маршрут; branch["rejected"] и branch["indeterminate"] содержат stopped_at_filter и stopped_at_step.
- result["candidates"] — одна таблица геометрического входа, оценки фильтров, статусы веток, причины остановки и filter_comparison_group.
- result["summary"] — количества входных, прошедших, отклонённых и indeterminate на каждом шаге каждого маршрута.

У точки, не дошедшей до следующего фильтра, статус этого фильтра not_evaluated. Сессионные оценки, полученные в другой ветке, могут быть видны в общей таблице; это не означает повторное прохождение точки по маршруту. Первоначальные статусы ранее выполненных фильтров не используются как результат нового запуска с другими настройками.

Диск: одна candidates.csv, summary.csv, metadata.json и необходимые таблицы эталонов. Запись CIF включается export_cif=True; export_rejected_cif управляет отдельными CIF отклонённых групп. По умолчанию CIF отключены. Один CIF содержит каркас и X-маркеры заданной группы; indeterminate-группа экспортируется отдельно, если непустая. Старые папки результатов не перезаписываются.

# Ручные заряды и полное разрешение радиусов

## Входные степени окисления

Для каждого элемента каркаса требуется явная степень окисления:

```python
result = run_search(
    structure_path,
    output_dir,
    probe_element="Li",
    probe_oxidation_state=1,
    geometry_oxidation_states={"Li": 1, "Ge": 4, "P": 5, "S": -2},
    export_cif=False,
)
```

Заряд пробника задаётся отдельно. `oxidation_states=...` — короткий совместимый псевдоним `geometry_oxidation_states`. Неполный словарь даёт ошибку до генерации кандидатов. Заряды должны быть целыми, поскольку дробный заряд не обозначает табличный ион Shannon. Зарядовая нейтральность не навязывается: структуры с искусственной вакансией могут иметь ненулевую формальную сумму зарядов.

Радиусные функции из `site_atomic_data.py` и `shannon_radii.py` остаются неизменёнными копиями. Рабочая обвязка сначала полностью назначает входные заряды; ветви BVAnalyzer в исходных функциях не вызываются. Данная схема задаёт один заряд на элемент; для смешанной валентности одного элемента потребуется отдельное расширение входного интерфейса, а не автоматическое угадывание.

## Порядок выбора радиуса

1. Точный **Shannon effective ionic radius**, с теми же элементом, зарядом, КЧ и заданным spin.
2. Если КЧ лежит между двумя доступными КЧ того же иона, линейная интерполяция радиуса между ближайшими нижним/верхним КЧ. Не интерполируются разные spin. Пример: Li+ КЧ 5 → между IV (0.59 Å) и VI (0.76 Å), получается 0.675 Å. O2− КЧ 5 → 1.39 Å, КЧ 7 → 1.41 Å.
3. Вне диапазона, либо при единственном доступном КЧ, ближайший табличный радиус **того же иона**. Примеры: Li+ КЧ 2/3 → значение IV 0.59 Å; Cl− → значение VI 1.81 Å; S2− → VI 1.84 Å. Размер выбранного КЧ и расстояние до требуемого КЧ видны по колонкам происхождения. Далёкое КЧ не становится точным совпадением: источник остаётся `shannon_nearest_cn`.
4. Если подходящих Shannon-данных нет вообще либо не удалось вычислить КЧ, берётся `Element.ionic_radii[charge]` для **точно заданного заряда**, если разрешён `geometry_allow_ionic_fallback=True` (дефолт). Средний радиус по другим степеням окисления не используется.
5. Явный `geometry_host_radius_overrides_A` или `geometry_probe_radius_override_A` имеет приоритет. Если нет ни табличного радиуса, ни разрешённого запасного значения, расчёт останавливается с указанием нужного override. Не создаются NaN-радиусы и формально успешные неопределённые решения.

Геометрические варианты IVSQ/IIIPY и другие специализированные записи не выбираются по одному числу соседей. При нескольких spin необходимо задать spin либо явно принять последний запасной источник/override.

## Почему не начинать с стандартного ionic_radius

В установленной базе pymatgen для наших ионов `Species.ionic_radius` совпадает со значениями Shannon crystal radius при одном из КЧ: Li+ 0.90 Å вместо effective ionic 0.76 Å для VI; Cl− 1.67 вместо 1.81 Å; S2− 1.70 вместо 1.84 Å. Смешивание точного effective ionic радиуса одного иона и такого запасного радиуса другого способно сдвинуть порог соприкосновения. Поэтому приоритет отдан единой effective ionic шкале Shannon и тому же заряду. Это наблюдение по установленной базе для перечисленных ионов, а не утверждение об одинаковом происхождении всех стандартных радиусов pymatgen.

Стандартный заряд-специфичный радиус остаётся последним явным запасным источником. Источники с разной шкалой не выдаются за точные Shannon-данные.

## Что записывается

Для каркаса: `radius_A`, `radius_source`, `radius_requested_coordination`, `radius_reference_coordinations`, `radius_reference_values_A`, `radius_reference_spins`, `radius_approximate`, `radius_convention`, `oxidation_source="user"`.

Для пробника — те же поля с префиксом `probe_`. Радиус вычисляется для каждой оставленной после симметрийного отсева полости в её неизменных координатах. Исходные `shannon_radius_A` могут быть пустыми: это запись об отсутствии точного значения, **выбранный radius_A всегда конечный**. Интерполированное/ближайшее значение — оценка, не новая табличная запись Shannon.

При успешном скрининге кандидаты получают только `passed` или `rejected`; `geometry_indeterminate` сохранён как пустая таблица для совместимости старых notebook. Проверяется полный радиус, порог 1.0. Для пограничных решений применяется явный допуск 0.005 Å; отдельно записывается strict_zero_overlap_fit. Масштабы поиска и радиусы не меняются ради заранее ожидаемого числа полостей.

## Ресурсы и повторные тесты

`export_cif=False` выключает генерацию CIF; CSV/JSON координат сохраняются. HTML, графики и прочие визуализации не создаются скринингом.

Повторно запускаются только LLZO–Ga, LGPS, LiCl и дефектный LiCl, ранее не имевшие подтверждённых кандидатов. LATP и обе структуры Li3PO4 не пересчитываются. В обновлённом тестовом notebook та же выборка и явно записанные ручные заряды всех материалов.

Ожидаемое наличие геометрических полостей в электролитах используется как диагностический контроль, а не как основание менять радиусы до положительного ответа. Количества по-прежнему описывают выбранную радиусную модель; энергетическая устойчивость здесь не рассчитывается.

## Пограничная известная вакансия

После устранения пропусков радиусов известная LiCl-вакансия оказалась отвергнута при строгом нуле: R_free=0.587025 Å, r_Li=0.590000 Å, зазор −0.002975 Å. Причина — критерий соприкосновения при приближённом Cl− радиусе для КЧ VI. Введён малый абсолютный допуск geometry_overlap_tolerance_A=0.005 Å, с отдельной записью strict_zero_overlap_fit. Это эмпирическая калибровка по известной контрольной позиции, а не доказанная универсальная погрешность Shannon. Настройка 0.0 доступна для математически строгого сравнения. Повторяется та же ограниченная выборка из четырёх соединений; остальные структуры и визуализации не запускаются.
